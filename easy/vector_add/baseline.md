## 2. 代码版本说明

- kernel：`c[i] = a[i] + b[i]`，**1 线程处理 1 元素**
- blockDim = **256**，`blocks = ceil(n/256)`
- 边界：`if (i < n)`
- 计时：`cudaEvent`，含 **warmup**（1 次不计时）+ **计时**（1 次）
- 数据生成：`std::mt19937(42)` + `uniform_real_distribution(-1, 1)`
- 校验：`fabs(expected - real) > 1e-2` 记为失败

## 4. 关键指标（n = 1<<20）

```
数据量        = 3 × 1048576 × 4 = 12,582,912 字节 ≈ 12.58 MB
实际带宽      = 12,582,912 / (0.0541 × 1e6) ≈ 232.6 GB/s
峰值带宽      = 320.06 GB/s
利用率        = 232.6 / 320.06 ≈ 72.7%
理论最短时间  = 12.58 MB / 320.06 GB/s ≈ 0.0393 ms
```

**固定开销地板**：小 n 稳定在 **≈ 0.006 ms**（launch 开销 + 计时分辨率）
→ 对应 design.md 假设 2 的「launch 税」。

---

## 5. 观察与风险点

1. **利用率 72.7%**，离访存上限还有约 **27%** 空间 → 值得优化。
2. 小 n（1~4096）耗时与 n 无关 → 完全被固定开销支配，**不能用来判断 kernel 性能**。
3. **单次测量**，噪声未平均（多次迭代取平均更可靠）。
4. `ncu` 在本平台不可用 → 瓶颈判断只能靠「计算访存比」理论（add 为 memory-bound）+ 利用率推算。
5. `fabs` 用了 double 版（应 `fabsf`），不影响结果，仅语义。

## 6. 优化目标

| 指标 | 基线 | 目标 |
|---|---|---|
| 利用率（n=1<<20） | 72.7% | **85%+** |
| 耗时（n=1<<20） | 0.0541 ms | **0.039 ~ 0.046 ms** |

**下一步（design.md 假设 1）**：`float4` 向量化，4 元素/线程，需处理
**16 字节对齐** 与 **n 非 4 倍数的尾部**。
